# Pose Parallax 実装仕様書

## 1. システム概要

Pose Parallaxは、複数の参加者がスマートフォンのWebブラウザから参加するリアルタイム協力型ゲームとする。

システムは以下で構成する。

- Webクライアント
- ゲームサーバー
- 3Dポーズ生成・表示
- 2Dポーズ生成
- スマートフォン上の姿勢推定
- ポーズマッチング
- リアルタイム同期

---

## 2. 参加フロー

1. QRコードからWebページへアクセス
2. 表示名を登録
3. 待機画面へ遷移
4. 主催者が参加受付を終了
5. ゲーム開始

各参加者には一意のPlayer IDを割り当てる。

対象端末はiPhoneおよびAndroidのスマートフォンとする。参加人数はポーズ役を含め2〜50人とする。同時に進行するゲームは1つとし、参加者を分けて運用する場合は管理者が手動で行う。複数チームの同時自動進行は初期実装の対象外とする。

---

## 3. ゲーム状態

サーバーは以下の状態を管理する。

- Waiting
- Round Setup
- Playing
- Round Result
- Final Result

各クライアントはWebSocketで現在のゲーム状態を受信する。

---

## 4. ラウンド生成

各ラウンド開始時に以下を行う。

1. ポーズ役をランダム選択
2. 3Dポーズを1つ選択
3. その他の参加者ごとにランダム視点を生成
4. 3Dポーズを各視点へ投影し、2D target keypointsを生成
5. 各クライアントへ必要な情報を送信

---

## 5. 3Dポーズ

3Dポーズは、関節位置を持つ3D skeletonとして管理する。

初期実装では事前定義ポーズを使用する。

ポーズ役の画面では3D skeletonを表示し、ユーザーが自由に回転して確認できるようにする。

ポーズ役の端末は、手に持つ、机に置く、ポケットに入れるなど自由とする。プレイ中に端末を見続けたり操作し続けたりすることを前提にしない。

---

## 6. ランダム視点

各観察者に対して以下の範囲からランダム視点を生成する。

- Azimuth: -180° ～ +180°
- Elevation: -30° ～ +30°

上記は視点範囲の初期値とする。管理者は視点範囲と視点の除外条件を変更し、以後のゲーム用のデフォルトとして保存できる。

生成した視点から3D skeletonを2Dへ投影する。

以下の場合は視点を破棄し、再生成する。

- 主要keypointが多く隠れる
- 左右のkeypointが過度に重なる
- 表示する12関節点のいずれかの組み合わせの距離が、設定された最小間隔を下回る（全高に対する比率。初期値0.08、管理者が0〜0.3で設定・保存可能）
- 2D姿勢として判別困難

視点角度自体は参加者へ表示しない。

---

## 7. クライアント側姿勢推定

観察者のスマートフォンではカメラ映像からリアルタイム姿勢推定を行う。

複数人が映る場合も画面中央の人物1人のみを判定対象とする。初期版では検出された最大4人から、肩・腰の中心が画面中央に最も近い人物を選択する。人物を検出できないフレームはマッチ不成立とする。

取得する情報は2D keypointsとconfidenceとする。

サーバーへ送信する基本情報（配列は概略。実際はMediaPipeの33点を送信する）：

```json
{
  "type": "pose",
  "round_id": "xxx",
  "keypoints": [
    [0.0, 0.0, 0.0]
  ]
}
```

---

## 8. ポーズマッチング

各参加者の推定keypointsと、割り当てられたtarget keypointsを比較する。

比較前に以下の正規化を行う。

- 平行移動補正
- スケール補正

体格差やカメラ距離の影響を小さくするため、座標距離は緩めに判定する。

マッチングでは主に以下を利用する。

- 関節角度
- limb direction
- 正規化keypoint位置

判定対象の関節点が設定された条件を満たした場合、その参加者をマッチ状態とする。管理者はスコア閾値、confidence閾値、判定対象関節、隠れた関節の扱い、マッチの継続時間などの判定条件を設定し、デフォルトとして保存できる。具体的な数値の初期値はiPhoneとAndroidの実機検証で決定する。

---

## 9. ラウンド終了条件

管理者は以下のクリア方式を選択できる。

- 達成保持方式（デフォルト）：一度マッチ条件を達成した参加者のクリアを保持し、ポーズ役以外の全参加者がクリアした時点でラウンド終了とする。
- 同時成立方式：ポーズ役以外の全参加者が同時にマッチ条件を満たした場合にラウンド終了とする。必要な継続時間は管理者が設定する。

設定はラウンド準備時に確定する。変更したデフォルト設定は次に準備するラウンドから適用し、進行中のラウンドには適用しない。

サーバーは以下を保存する。

- 開始時刻
- 終了時刻
- クリアタイム
- 各参加者のマッチ完了時刻
- ポーズ役
- 使用したポーズ
- 使用した視点

---

## 10. ラウンド進行

複数ラウンドを実施する。

可能な限り、各参加者がポーズ役を経験できるようにポーズ役を選択する。

ラウンド終了後、結果画面を表示し、次のラウンドへ進む。

管理者は切断・途中退出・時間切れなどに対処するため、参加者の除外、ラウンドの中止・スキップ、ゲームの終了を操作できるようにする。再接続時はCookieで同じ参加者へ復帰する。ポーズ役を除外した場合はそのラウンドを中止する。観察者の除外後は残りの観察者で終了条件を再評価し、観察者が0人の場合は中止する。

---

## 11. 画面構成

### 管理者画面

- 参加受付の開始・終了、ゲーム開始
- 参加者管理と除外
- ラウンドの中止・スキップ、ゲーム終了
- クリア方式の選択
- 視点生成とポーズ判定の設定
- 設定のデフォルト保存

管理者操作は参加者用画面と分離し、管理者だけが実行できるようにする。初期版は管理者パスワードとHttpOnly Cookieによるセッション認証を使用する。

### 待機画面

- イベント名
- 自分の表示名
- 参加者一覧
- Waiting表示

### ポーズ役画面

- 3D skeleton
- 回転操作
- ラウンド番号
- 経過時間
- 他参加者のクリア状況

### 観察者画面

- カメラ映像
- Target 2D skeleton
- 推定skeleton
- Match Score
- Clear状態
- 経過時間

### 結果画面

- クリアタイム
- 各参加者の結果
- ベストタイム
- ラウンド履歴

## 12. 通信

リアルタイム同期にはWebSocketを使用する。

初期版は個別の状態変更イベントではなく、再接続時にも復元できる状態スナップショットを配信する。

- state：現在の状態、参加者、本人向けの問題、結果（最大2回/秒）
- ready / unready：ラウンドの準備完了・取消
- pose：観察者の関節座標とround_id
- feedback：本人のスコア・一致状況・クリア状態

参加、管理者ログイン、設定保存、進行操作はHTTP APIを使用する。参加者IDはセッションから決定し、クライアントが申告するIDや時刻は採点に使用しない。

## 14. データ保存

最低限以下を保存する。

- Event
- Player
- Round
- Pose
- Viewpoint
- Result
- Admin Settings（保存したデフォルト設定）

画像保存とアルバムは初期実装の対象外とし、Imageは将来拡張として扱う。

---

## 15. 通信・プライバシー方針

姿勢推定は原則として各スマートフォン上で実行する。

初期実装では画像フレームと連続したカメラ映像をサーバーへ送信・保存しない。姿勢判定用には2D keypointsとconfidenceを送信する。

---

## 16. 会場内サーバー

会場内サーバーにWebクライアントとゲームサーバーを配置し、参加者のスマートフォンから会場ネットワーク経由で接続する。カメラ利用のためHTTPSを使用し、WebSocketもWSSで接続する。

両OSのブラウザが信頼できる証明書、名前解決、スマートフォンからサーバーへの到達性を用意する。会場ネットワークの端末間通信制限も確認する。

会場ではインターネット接続を利用できる。初期実装では完全オフライン運用を必須としない。Webクライアントとゲームサーバーは会場内サーバーで運用し、推論モデル、JavaScript、WASMなどの配信元は実装時に決定する。

## 17. 初期実装の検証項目

- iPhoneとAndroidでのカメラ利用、推論速度、発熱と継続動作
- MediaPipe GPU delegateの利用可否とCPU fallbackでの実用性
- 2人および最大50人でのゲーム進行と通信負荷
- 中央人物の選択、人物の入れ替わり、未検出時の挙動
- 視点・ポーズごとの判定成立性と左右の対応
- 両クリア方式、管理者操作、切断と再接続
- 会場ネットワークでのHTTPS・WSS接続

具体的な判定方法・復旧ルールと初期版の制限は [初期版の設計判断](Implementation_Notes.md) を参照する。
