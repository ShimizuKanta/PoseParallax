# Pose Parallax：起動・参加とデータの扱い

主催者がPCでサーバーを起動し、参加者はスマートフォンのブラウザから遊びます。主催者はプレイ中、PCとサーバーを起動したままにしてください。

## 対応環境

| 利用する人 | 対象環境 |
| --- | --- |
| 参加者 | カメラのあるiPhoneのSafari、AndroidのChrome |
| Windowsアプリの主催者 | Windows 10 / 11、x64のPC |
| ソース版の主催者 | Python 3.11以上、Node.js 22.12以上（22系推奨）、OpenSSLのある環境 |

- 参加者は2〜50人です。管理者PCを参加者として登録した場合も人数に含みます。同時に進行できるゲームは1つです。
- 画面は日本語・英語を選べます。参加者のスマートフォンへの専用アプリのインストールは不要です。
- スマートフォンのカメラ利用には、ブラウザが信頼できるHTTPS接続とカメラの許可が必要です。
- 対象環境はすべての機種での動作確認を意味しません。開催前に、使用するiPhone・Androidと参加台数で接続・カメラ・姿勢判定を確認してください。

Windowsアプリのコードは `feat/windows-desktop-app` ブランチにあります。ソース版は `main` とWindowsブランチの両方で起動できます。

## Windowsアプリで起動する

Windowsの配布物を入手した場合は、次の手順で起動します。

1. `PoseParallax-Setup-<バージョン>-windows-x64.exe` を実行してインストールします。ポータブル版の場合はZIPをすべて展開し、展開したフォルダー内の `PoseParallax.exe` を開きます。EXEだけを移動しないでください。
2. スタートメニューまたはデスクトップから **Pose Parallax** を開きます。標準の「インターネット（証明書不要）」で自動起動します。
3. 「稼働中」になったら、表示されたQRコードを参加者に案内します。
4. 主催者は「管理者パスワードをコピー」→「管理画面を開く」でログインします。このボタンから開く管理画面は主催者PC内部の専用ポートのURLです。公開URLやLAN内の別端末からは管理者ログイン・管理操作を受け付けません。
5. 終了するときは「サーバー停止」を押すか、ウィンドウを閉じて停止を確認します。

この接続方法では、主催者PCとスマートフォンの両方にインターネット接続が必要です。同じWi-Fiへの接続、参加者のCloudflareアカウント作成、CA証明書の登録は不要です。

起動・再接続で参加URLが変わります。新しいURLはQRコードへ自動反映されるため、毎回その時点のQRを案内してください。別のURLへは、参加者のブラウザのログイン状態を引き継げません。次のグループの受付を開始した場合も招待情報が更新され、古いQRからは新規参加できなくなります。

接続に失敗した場合はインターネット接続を確認して再試行します。「詳細」から状態・ログを確認できます。Cloudflare Quick Tunnelには稼働保証がなく、接続先ネットワークでトンネル通信が制限されている場合も利用できません。[Cloudflareの公式説明](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)

## ソース版でLAN内に起動する

次はLinux / macOSでの手順です。初回の依存パッケージと姿勢モデルの取得にはインターネット接続が必要です。

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.lock
npm ci
npm run assets
npm run build
npm start
```

起動するとLAN IPを自動検出し、会場CAとHTTPS証明書を生成します。主催者PCとスマートフォンを同じLANに接続し、端末からPCのTCP 8000・8443へ接続できるようにしてください。

1. 起動ログに表示される `http://LAN-IP:8000/` をスマートフォンで開きます。
2. 主催者が案内したページであることを確認し、ページのOS別手順に従って会場CAを登録・信頼します。主催者PCのブラウザにも登録が必要です。
3. `https://LAN-IP:8443/admin` から管理者ログインします。パスワードは初回起動で生成する `data/admin-password.txt` にあります。
4. 管理画面のゲーム参加QRを参加者に案内します。

Windowsアプリでも、停止中に「詳細」→「会場LAN（証明書登録が必要）」を選べば同様のLAN接続を利用できます。LAN接続では、モデル取得後のゲーム通信にCloudflareを使いません。

既存のHTTPS証明書・Docker・ポート変更などの運用方法は [README](../README.md) を参照してください。

## スマートフォンから参加する

1. 主催者のQRコードを読み取り、ブラウザで参加ページを開きます。
2. 表示名を入力します。他の参加者にも表示されるため、ニックネームを使えます。
3. 主催者が「ゲームを準備」を押したら、自分の役割を確認します。
4. ポーズ役は3Dのお手本を確認し、ポーズを取って「ポーズの準備完了」を押します。
5. 観察者はカメラを起動して利用を許可し、中央にポーズ役の全身を映して「カメラの準備完了」を押します。
6. 全員の準備後、主催者がラウンドを開始します。観察者は自分の2Dお手本に合う視点を探します。

プレイ中はブラウザを表示したままにしてください。画面ロックや別タブへの切り替え中はカメラ判定が止まります。「詳細」から判定条件・参加者・結果を確認できます。結果画面では3Dのポーズを見直し、自分のお手本の視点へ戻せます。[画面と言語の案内](UI_Guide.md)

## 通信するデータ

カメラ映像はスマートフォン内で姿勢推定に使用します。**アプリは映像・写真をサーバーへ送信せず、保存もしません。** 画面中央の人物を採点対象として、その人物の33点の座標と信頼度を主催者PCへ送ります。

| 接続方法 | 通信経路 |
| --- | --- |
| Windowsアプリの標準接続 | スマートフォン ↔ Cloudflare ↔ 主催者PC |
| 会場LAN接続 | スマートフォン ↔ 主催者PC（LAN内） |

標準接続でCloudflareを経由するデータには、ページ・姿勢モデル・表示名・姿勢の座標と信頼度・スコア・結果・セッション情報などがあります。HTTPS接続で通信を保護します。

Windowsアプリでは、管理者ログイン・管理操作をPC内部の専用ポートに限定しており、その管理通信はCloudflareを経由しません。ソース版にはこのWindows専用の制限はなく、管理用URLを外部へ中継する構成では、パスワードと管理操作もその中継サービスを経由します。

参加前は、参加者名・スコア・ゲーム結果を表示しません。参加には主催者のQRに含まれる招待トークンが必要です。トークンはURLの `#invite=…` に含め、名前と一緒に送信します。QRを読む以外の追加入力はありません。URLから招待情報を削除すると参加できません。

招待トークンは次のグループを開始すると更新されます。同じグループでの再起動では維持します。QRや招待URLを共有された人も参加できるため、参加者だけへ案内してください。招待URLを使わずに開いた場合は、最新のQRを読み直します。

新規参加登録の試行は1分間にブラウザ単位で3回、同一IPで60回、サーバー全体で120回に制限します。通常の再接続はこの制限の対象外です。制限が表示されたら1分ほど待って再試行してください。これは大量登録を抑える対策であり、1人が複数のブラウザや端末を使うことを完全に防ぐものではありません。

## 主催者PCに保存するデータ

| 保存場所 | 内容 |
| --- | --- |
| Windowsアプリ：`%LOCALAPPDATA%\PoseParallax` | ゲームデータ・設定・認証情報・起動ログ |
| ソース版：プロジェクト内の `data/` | ゲームデータ・設定・認証情報 |

`POSE_DATA_DIR` を設定した場合は、その指定先に保存します。

- `pose.sqlite3`：招待トークン、参加者の表示名・ID、設定、ラウンドのお手本と視点、クリア時刻・結果、セッションの認証情報など。採点用のカメラ座標をフレームごとに保存する機能はありません。
- `admin-password.txt`：管理者パスワード。
- `tls/`：LAN接続で生成する会場CA・サーバー証明書・秘密鍵。標準のトンネル接続ではこれらの証明書生成は不要です。
- Windowsアプリの `desktop.log`：起動・停止・障害のログ。参加URLやPC上のファイルパスが含まれることがあります。
- Windowsアプリの `ui-preferences.json`：起動画面の言語。

別グループの開始やアプリ終了だけでは、過去のゲームデータを削除しません。Windowsアプリの更新・アンインストールでも保存データは残ります。

データも完全に削除する場合は、サーバーとアプリを停止してから上記の保存フォルダーを削除します。パスワード・設定・結果も消え、LAN接続では新しい会場CAの登録が必要になります。設定した保存先以外にもバックアップがあれば、必要に応じて削除してください。

ソースコードや配布物を公開するときは、**保存フォルダー・管理者パスワード・証明書の秘密鍵を含めないでください**。不具合の報告時にログを共有する場合も、参加URLや個人のファイルパスを確認してください。

参加者のブラウザにも、再接続用のセッションCookie（有効期間は24時間）と選択した言語を保存します。ブラウザのサイトデータを削除すると、参加状態と言語設定が消えます。
